이 페이지는 계정 쪽에서 가장 자주 묻는 질문에 답합니다. "조작"이 필요한 일은 모두 콘솔에서 합니다. CLI는 이 컴퓨터의 로그인과 상태 확인만 담당합니다.

## 로그인과 계정

**콘솔은 어떤 로그인 방식을 지원하나요?** 이메일 인증 코드, 휴대폰 SMS 인증 코드, WeChat. 조직은 구성원 로그인용 SSO 신원 공급자를 별도로 설정할 수 있습니다. CLI 자체는 로그인을 하지 않으며, 콘솔에서 만든 개인 액세스 토큰(PAT)으로 초기화를 완료합니다.

**계정에 이메일을 연결하면 무엇이 좋은가요?** 플랫폼은 다음 이메일을 보냅니다: 승인 대기와 결과, 조직 초대, 잔액이 임계값 미만일 때의 경고(같은 계정에 하루 최대 한 통), 새 앱 키 생성 알림(파생 경로 포함, 키 평문은 절대 포함하지 않음), 플랜 만료와 유예 기간 알림, 조직 예산 경고와 초과 알림(조직 소유자 / 관리자에게 발송, 같은 조직에서 같은 달 같은 종류는 최대 한 통), 조직 해산 시 잔액을 바꿔 발급한 카드 키. 이메일을 연결하지 않으면 조용히 건너뛰며, 어떤 기능에도 영향이 없습니다.

**한 사람이 여러 조직을 가질 수 있나요?** 가능합니다. 개인 계정은 조직을 만들거나 가입할 수 있으며, 조직에는 구성원, 초대, 팀, 거버넌스 정책이 있습니다. 플랜은 계정(개인 또는 조직)에 걸려 있습니다.

**계정을 어떻게 삭제하나요?** 콘솔에 계정 익명화 절차가 있습니다(먼저 챌린지로 확인을 시작하고, 그다음 실행). 삭제 전에 남은 잔액과 미결제 청구서를 먼저 처리하세요.

## 개인 액세스 토큰(PAT)과 디바이스 키

**PAT는 어디에서 만들고 어떻게 쓰나요?** 콘솔 "API 키" 페이지에서 만들며, 한 번만 표시되므로 즉시 복사하세요. 용도는 하나뿐입니다: `tansr init`으로 이 컴퓨터의 CLI에 로그인(마스크 입력, 또는 CI에서는 `TANSR_PAT` 환경 변수). PAT는 당신 본인을 나타냅니다.

**`tansr init` 뒤에 무슨 일이 일어났나요?** 마법사가 PAT를 검증 → **이 기기**를 위한 앱 키 하나를 파생(`cli:<호스트 이름>:<디바이스 id>`로 명명) → 운영 체제 키체인에 기록 → 요약 카드 표시(계정 지문, 잔액, 최근 사용량, 사용 가능한 모델 수, 파생 키 유효 기간). 그 뒤 `tansr`를 바로 쓸 수 있으며, 모델 목록과 가격표는 플랫폼이 배포합니다.

**PAT를 잃었거나 유출이 의심돼요.** 콘솔에서 그 PAT를 삭제하거나 비활성화하고(복구 가능과 영구 삭제의 두 단계 지원), 새로 하나 만들고, 각 기기에서 `tansr init --fresh`로 다시 로그인합니다.

**디바이스 키는 만료되나요?** 만료됩니다. 만료가 가까우면 세션 안에 "키가 곧 만료됩니다" 안내가 표시되며, `tansr init`을 다시 실행하면 교체되어 기간이 연장됩니다. 더 이상 쓰지 않는 기기는 콘솔에서 그 디바이스 키를 비활성화하거나, 그 기기에서 `tansr logout`합니다. `tansr logout`은 **PAT를 폐기하지 않습니다.**

**여러 컴퓨터가 같은 호스트 이름이면 서로 밀어내나요?** 아니요. 각 기기에는 8자리 무작위 디바이스 id가 키 이름에 들어가므로, 복제한 가상 머신과 회사 통일 이미지도 각자의 키를 가집니다.

**요약 카드가 자격 증명이 평문 파일로 폴백되었다고 해요.** 이 컴퓨터의 키체인을 사용할 수 없다는 뜻입니다(데스크톱 세션이 없는 Linux나 컨테이너에서 흔함). 자격 증명은 0600 권한 파일로 저장됩니다. `tansr doctor`의 자격 증명 저장소 섹션이 계속 귀속을 표시합니다. 키체인을 고칠 수 있으면 고치고, 안 되면 그 디렉터리를 다른 사용자가 읽지 못하게 하세요.

## 앱과 앱 키(개발자)

**앱 키와 PAT는 무엇이 다른가요?** 앱 키(appid / appkey)는 당신의 **앱**을 나타내며, 콘솔 "앱" 페이지에서 발급하고, 당신의 서버 쪽에만 두며, 최종 사용자를 위한 단기 토큰을 발급하는 데 씁니다. 최종 사용자는 tansr 계정이 필요 없습니다. PAT는 당신 본인을 나타내며 CLI에만 씁니다.

**앱을 만들 때 어떤 유형을 선택하나요?** 데스크톱 앱(Electron 등) / 모바일 앱(Android / iOS / HarmonyOS, 세션 서비스 경유) / 서버 앱. 앱 하나에 플랫폼 하나, 여러 플랫폼이면 여러 appid로 폐기 범위와 사용량 귀속을 나눕니다.

**appkey가 유출됐어요.** 콘솔 "앱" 페이지에서 교체하고, 서버 환경 변수를 업데이트한 뒤 재시작합니다. 이전 appkey는 즉시 무효화됩니다. 최종 사용자 단위로 그 기존 토큰을 폐기하거나, 앱 전체를 비활성화할 수도 있습니다. 앱에는 IP 허용 목록도 설정할 수 있습니다(목록 밖은 `app_ip_denied`).

**새로 발급된 앱 키는 요청 서명을 요구하나요?** 네, 기본적으로 강제입니다. 당신의 발급 엔드포인트는 `x-tansr-ts` / `x-tansr-nonce` / `x-tansr-sign` 세 헤더를 붙여야 하며, 서명하지 않으면 항상 `401 signature_invalid`입니다. 공식 예제 `examples/token-server`에 바로 쓸 수 있는 구현이 있습니다.

## 플랜과 동시 실행

**기능이 등급별로 나뉘나요?** 아니요. 판정자, 메모리, 컨텍스트 스킴, 미디어, MCP, 조직 거버넌스는 전 등급이 같은 제품입니다. 등급의 차이는 동시 실행 수, 앱 수, 구성원 수, 모델 요금과 서비스만입니다. 테스트 기간에 만든 것은 등급을 올려도 수정 없이 동작합니다.

| 등급 | 대상 | 동시 실행 상한 | 앱 수 | 모델 요금 |
|---|---|---|---|---|
| 개인 | 개인 사용자, CLI만 | 등급 없음 | 0(앱을 만들면 테스트 기간으로 들어감) | 정가 |
| 테스트 기간 | 통합 테스트, 기업 시작 | 10 | 3 | 정가. 플랜 요금은 전액 모델 잔액으로 전환 |
| 소규모 | 독립 소프트웨어 제작자 | 100 | 10 | 정가 |
| 중규모 | 입문 기업 | 1,000 | 32 | 협의 가격 |
| 대규모 | 플래그십 기업 | 10,000 | 100 | 협의 가격. 전용 업스트림 선택 가능 |

가격, 월 결제 / 연 결제 옵션, 구매 진입점은 콘솔 "플랜" 페이지를 기준으로 합니다.

**동시 실행은 어떻게 계산하나요?** 계정(개인 / 조직) 아래 **5분 하트비트 창 안의 활성 세션 수**의 최대치입니다. CLI 구성원 세션과 당신의 SDK / 세션 서비스 최종 사용자 세션을 합산하며, 같은 계정 아래에서는 세션 id로 중복을 제거합니다. 하드 캡 = 등급 × 1.1(10% 흔들림 유예). 80% / 100% 수위에서는 플랫폼이 하루 한 번 경고합니다.

**상한에 닿으면 무슨 일이 생기나요?** 플랫폼은 `429 plan_concurrency_exceeded`를 `Retry-After: 30`과 함께 반환합니다. **새 세션만 거부하고 기존 세션은 끊지 않습니다.** CLI TUI는 배너 하나를 띄우고 플랜 페이지 링크를 붙이며, 자동으로 재시도하지 않습니다. 30초 뒤 수동으로 다시 보내면 됩니다. 세션 서비스 형태에서는 최종 사용자에게 "나중에 다시 시도"만 보이며, 할당량 사실은 당신의 서버 로그에 들어갑니다.

**테스트 기간에는 또 어떤 상한이 있나요?** 월간 서로 다른 최종 사용자 수 100(토큰 발급 경로만). 상한 도달은 `plan_end_users_exceeded`. 앱 수, 조직 구성원 수가 등급 상한에 이르면 새로 만들기만 금지하고, 기존 것은 비활성화하지 않습니다.

**만료되면 어떻게 되나요?** 14일 유예 기간이 있습니다. 유예 후에는 테스트 기간 상한으로 돌아가며, 앱은 사라지지 않습니다. `tansr doctor`의 플랜 줄은 세 상태 중 하나를 표시합니다: 유효 / 만료되어 유예 기간 중 / 테스트 기간 상한으로 돌아감(원래 등급 이름 첨부). 콘솔에서 플랜, 견적, 플랜 사용량을 볼 수 있으며, 카드 코드 교환도 지원합니다.

**개인 등급인데 왜 doctor가 "플랜 요금 없음"이라고 하나요?** 개인이 CLI를 쓰면 플랜 요금을 받지 않고 정가로 잔액에서 차감합니다. 이 줄은 고장이 아니며 차단 문제에 들어가지 않습니다.

## 잔액, 청구서, 인보이스

**어떻게 충전하나요?** 콘솔 "잔액" 페이지에서 주문합니다(주문 페이지에서 과거 주문 상태를 볼 수 있음). 잔액이 0이거나 얻을 수 없을 때 `tansr init` 요약 카드가 경고하고 첫 충전 안내를 붙이지만, 차단하지는 않습니다.

**잔액이 적어지면 어떤 안내가 있나요?** TUI 상태 표시줄의 잔액 부분은 1위안 미만이면 항상 보이는 경고로 바뀝니다. 콘솔은 경고 임계값에 따라 배너를 표시합니다. 이메일을 연결했으면 경고 메일을 받습니다(하루 최대 한 통). 잔액이 소진되면 플랫폼 모델 호출은 서버 쪽 과금 게이트가 거부하며(`insufficient_balance`), 로컬 기능에는 영향이 없습니다.

**사용량과 청구서는 어디에서 보나요?** 콘솔 사용량 페이지(앱별 / 구성원별 분해), 월간 청구서 페이지. CLI에서는 `/cost` `/usage`로 이 세션을 봅니다. 개발자가 최종 사용자에 대해 대조하려면 `GET /v1/app-usage/by-end-user`(금액 포함)를 씁니다. 단말 자가 조회 `GET /v1/my-usage`에는 금액 필드가 절대 없습니다.

**인보이스는 어떻게 발행하나요?** 콘솔에서 발행 정보(인보이스 수신자 정보 페이지)를 입력한 뒤 청구서별로 신청합니다.

**플랜을 환불할 수 있나요?** 자격 조건이 있습니다. 충족하지 않으면 `refund_not_eligible`을 반환하며, 콘솔 안내를 기준으로 합니다.

## 그래도 안 되면

- 로그인 / 키 문제: 먼저 `tansr doctor`를 실행하고, 자격 증명 저장소 섹션과 `localProviders` 섹션을 스크린숏하거나 복사합니다(키 값은 포함하지 않음).
- 과금 문제: 계정 지문(`tansr init` 요약 카드에 표시되는 형태이며, PAT 자체가 아님), 주문 번호 또는 청구 월을 준비합니다.
- 그다음 [지원팀에 문의](/ko/support/contact/)하세요.
