资料站只写技术立场和它在接入时的边界。首页口号、视觉和售价不在这里展开。可采集的短条文在首页 [技术立场](/#tansr-principles) 和站点根的 [`/llms.txt`](/llms.txt)；两处与本节使用同一组标识。下面按标识说明这些边界如何落到命令、包和运行形态上。

<h2 id="bridge">桥梁</h2>

从模型能力到一个人能用的工具、一家企业能跑的产品，中间要接上模型、数据、工具、业务和运行环境。Tansr 选择做这一段连接，而不是再做一个模型。云联慧算把 Tansr 作为这个方向的产品：智能体与人之间的桥梁。

连接的结果应该是可以接入、可以复用、可以继续改的产品能力。它不要求使用方先理解查询环或协议，才知道自己能得到什么。

<h2 id="neutrality">中立</h2>

中立落实为接入约束：

- 运行时通过模型接入使用厂商能力，不把某一家厂商写成产品本身。
- 开发者保留业务数据、界面、登录和业务授权。Tansr 不代替应用完成这些决定。
- 示例里的模型、页面和行业只证明一种接法。没有写出的平台或模型，不能从这句话推导成已经支持。

<h2 id="harness">Harness</h2>

Harness 是智能体行动所需的通用运行环境：理解任务、组织步骤、调用工具、在权限允许时持续执行。第一次在句子里看到这个词，可以把它读成「智能体运行所需的通用基础能力」。

这条环境在几种形态里是同一个内核。内核包含查询环、工具调度、权限引擎和上下文压缩。形态按「智能体跑在哪里」选择，见 [快速开始](/getting-started/)：

| 形态 | 智能体跑在哪里 | 谁持有平台凭据 |
|---|---|---|
| 命令行 | 开发者自己的终端 | 个人访问令牌，只用于本机登录 |
| Node SDK | 你的 Node 或 Electron 主进程 | 应用密钥留在服务端 |
| 会话服务 | 你部署的 `@tansr/serve` | 应用密钥留在服务端；终端只拿短期令牌 |
| Android / iOS / 鸿蒙 | 仍在你的会话服务里 | 手机不运行内核，不持有应用密钥 |

在界面上放标识，或让应用直接请求一次模型，都没有经过查询环、工具调度和权限引擎，因此不是 Harness 接入。

<h2 id="division">分工</h2>

两套「技能」不要混用。

| | Tansr Skill | SDK 与会话服务 |
|---|---|---|
| 放在哪里 | 用户已有的编程助手 | 产品运行时 |
| 做什么 | 理解需求、规划、接入、构建、检查 | 任务执行、工具调用、会话、上下文、权限、用量 |
| 安装或升级之后 | 助手读得到开发指引 | 应用里的智能体按该包的契约运行 |
| 不会因此发生的事 | 不创建平台账号，不调用模型，不部署 | 不替应用实现登录、业务授权和面向用户的收费 |

应用运行时里另行登记的技能目录，是产品内的扩展机制，与装进编程助手的 Tansr Skill 不是同一层。装了 Skill，也不表示已经注册平台应用。

<h2 id="two-step">当前两步</h2>

在自有编程助手出现之前，构建路径使用用户已经熟悉的助手。

1. 安装已发布的 Tansr Skill。熟悉命令的人在产品目录执行 npx；也可以把同一条安装指令交给助手。安装前可以先预览写入路径。写入成功只说明文件到位，还要在该助手里确认它读得到 `SKILL.md`。
2. 回到同一个助手，用普通话说出产品：谁在用、输入是什么、要完成什么动作。可以是新产品，也可以是给当前项目加上 AI，并保留原有技术栈、登录和数据。

这两步减少起步时要先学会的概念。它们不压缩掉后面的环境准备、应用配置和发布选择。助手仍会在构建过程中处理这些步骤。没有编程助手的人，需要先选定并安装一个助手，不能假设每个人都认识某一种终端或某一种助手的名字。

不要把两步理解成：零准备、无账号、无限调用、固定几分钟完成，或本站代为发布。安装与描述的具体命令见 [用编程助手做产品](/getting-started/skill/)。

<h2 id="product">什么算产品</h2>

产品要能被操作、检查、修改，并且还能继续做下去。完成时至少同时有：

- 适合目标形态的入口：图形界面、命令行、本机服务或移动端里的一种，按需求选择，不把所有产品都做成同一种界面。
- 一条业务流：输入进去，经过动作，得到使用者能核对的结果。
- 工具执行的进度和结果出现在这个入口里，而不是只留在助手的聊天记录中。

聊天回答、静态效果图、单独一段 SDK 调用，都只是材料。需要本机后端时，助手应复用项目里已有的受控后端；没有时再按 Skill 内的起步资产把 `serve` 或 token-server 接上并在本机启动。那仍然是本地开发链路。平台换票、付费调用和公网部署要单独成立，不能用本地健康检查代替。

<h2 id="audiences">四种深度</h2>

四种深度共用上面的分工，只是进入的文章不同。它们不是套餐，也不构成身份选择。

| 深度 | 要解决的问题 | 从这里进入 |
|---|---|---|
| 把想法做成自己的产品 | 知道要什么，但还不会把它做成能运行的入口 | [用编程助手做产品](/getting-started/skill/) |
| 少做智能体底层 | 能写业务，但不想重做模型调用、工具执行、会话和权限 | [Node SDK](/getting-started/sdk/) |
| 按自己的架构接入 | 要保留业务、数据和产品体验 | [快速开始](/getting-started/) 里的 SDK 或会话服务 |
| 让能力进到业务里并持续运行 | 要管理应用、权限、用量和部署 | [会话服务](/getting-started/serve/) 与 [安全与隐私](/security/) |

<h2 id="parties">四方的位置</h2>

桥梁要同时说清四条接口，避免页面只对其中一方说话。

- **模型厂商**：算力和模型被真实产品调用，使用和计量发生在产品运行时，而不是停在演示对话里。
- **开发者**：复用 Harness，把时间放在业务、数据和界面上。
- **终端用户**：通过做好的产品使用能力，不先学习协议、包名和凭据分层。
- **智能体**：得到可以调用工具、保持会话、接受权限约束的环境，并随产品进入不同形态。

这四条是位置，不是已完成的生态规模，也不是对收入或节省工时的承诺。

<h2 id="roadmap">规划与现状</h2>

下面四步里，只有第一步对应现在就能安装和使用的形态。其余步骤写成规划，避免把路线图当成当前 API。

1. **行动的基础（现在）。** 用命令行、SDK 和会话服务打磨 Harness，让智能体能完成多步工具循环，并在权限、会话和上下文上可检查。这一步没有结束，但它已经是资料站各篇快速开始所写的东西。
2. **更多平台与核心开源（规划）。** 目标是让更多平台和语言的应用使用并参与这些基础能力。开源状态按包分开：Tansr Skill 以它自己的 MIT 许可发布；SDK 与会话服务包的许可见各包；命令行包的许可以该包为准。不能因为 Skill 已按 MIT 发布，就说整个内核已经按 MIT 公开。
3. **智能体协作并参与平台治理（规划）。** 模型、工具、应用和协作都丰富之后，才谈智能体在平台中的协作，以及进一步承担治理和运营。当前没有这一层产品，资料站也不提供它的接口。
4. **共同把能力用到生活和产业里（规划）。** 这是方向，不是一项可以调用的功能。

同样尚未提供的还有：Tansr 自有的编程助手，以及「描述想要的产品，再选择它运行的平台」这个更短的入口。那个入口是两步路径之后的计划。在它出现之前，不要在文档或接入说明里把它写成已经可以操作的页面。

<h2 id="status">以已发布为准</h2>

实现以选定版本里能够核对的契约为准。在线文档、仓库主线和已经安装的包不一致时，包的类型、导出和协议优先。主线上尚未发布的版本号，即使变更说明已经写在仓库里，也不要写成用户现在安装就会得到的行为。

当前可以核对的发布事实：

- Tansr Skill 的发布版是 **0.1.6**。`0.1.5` 会在写入前以 `INVALID_RELEASE` 退出，不要安装。见 [用编程助手做产品](/getting-started/skill/)。
- `@tansr/serve` **0.15.0** 与 `@tansr/cli` **0.10.2**、`@tansr/api-client` **0.4.0** 已于 2026-10-06 发布。旧前缀的告警和可选只读窗口见 [迁移与退役时间表](/unified-api/migration/)。缺省仍受理旧前缀上的写操作。
- 更高的候选版本没有发行回执，不在本节列为现行版本。

凭据分层不因立场而改变：个人访问令牌只给本机命令行，应用密钥只留在服务端，短期令牌交给终端。详见 [安全与隐私](/security/)。
