<h2 id="faq" class="home-section-title">よくある質問のグループ</h2>

<FaqGroups />

ここは tansr のヘルプセンターです。開発者ドキュメントは「どう使うか」を説明し、ここでは「何が起きたのか、誰に相談すべきか」に答えます。まず下のグループからあなたの質問を探してください。見つからなければ、最後の 3 つの入口へ進んでください。

## 3 つの入口

| 解決したいこと | 行き先 |
|---|---|
| ログインできない、キーを失った、残高とプラン、インボイス | [アカウントと請求](/ja/support/account/) |
| エラーが出た、`tansr doctor` の出力が読めない、あるエラーコードの意味 | [トラブルシューティングガイド](/ja/support/troubleshooting/) |
| 上記で解決しない、または問題を報告したい | [サポートに連絡](/ja/support/contact/) |

## 導入とインストール

**どの記事から始めるべき？** エージェントをどこで動かすかで決まります。ターミナルで自分が使うなら CLI、Node / Electron プログラムに組み込むなら SDK、自分のユーザーにエージェントを提供するならセッションサービス、モバイルはセッションサービス経由で Android / iOS SDK を接続します。道の選び方の表は[クイックスタート](/ja/getting-started/)にあります。

**どんな実行環境が必要？** CLI の npm パッケージと 2 つの npm ライブラリはいずれも Node.js ≥ 22.19 が必要です。単一ファイル実行版はランタイムを同梱しています。Android は minSdk 26、iOS は 16+。

**`npm i -g @tansr/cli` の後、コマンド名は？** パッケージ名は `@tansr/cli`、コマンド名は `tansr` です。`tansr --version` でインストールを確認します。

**どう更新する？** `tansr update` でチェックし、`--install` を付けた場合だけインストールします。TUI 内では `/update`。起動時に自動チェックは行いません。組織は `TANSR_UPDATE_PINNED_VERSION` でバージョンを固定できます。

**プラットフォームを使わず、自分のモデルキーだけを使いたいのですが？** できます。`TANSR_ESCAPE_LOCAL=1` を設定して完全ローカルモードに入り、`.tansr/settings.json` で provider を宣言します（API キーは環境変数名だけを書く）。プラットフォーム機能（リモートモデル、使用量、残高）は全体が停止します。

## アカウントとキー

**PAT、アプリキー、エンドユーザートークンは何が違う？** PAT はあなた本人を表し、`tansr init` でこのマシンにログインするためだけに使います。アプリキー（appid / appkey）はあなたのアプリを表し、サーバー側にだけ置きます。エンドユーザートークンは、サーバーが appkey であるユーザー向けに発行する短期の認証情報です。詳細は[アカウントと請求](/ja/support/account/)と[セキュリティとプライバシー](/ja/security/)を参照。

**`tansr init` で PAT が無効または期限切れと言われたら？** コンソールで PAT を新しく作成し、`tansr init --fresh` で再ログインします。

**パソコンを替えたら再ログインが必要？** はい。各デバイスが自分の派生キーを持ちます。`tansr init` を再実行するだけです。古いデバイスのキーは影響を受けず、コンソールで無効化できます。

**`tansr logout` で PAT は失効する？** しません。このマシンの認証情報を消去し、このマシンの派生キーを無効化するだけです。PAT はコンソールであなた自身が管理します。

## プランと課金

**個人で CLI を使うのにプラン料金は必要？** 不要です。個人ティアにはプラン料金がなく、モデルは定価で残高から差し引かれます。`tansr doctor` が「プラン：個人（CLI のみ、プラン料金なし）」と表示するのは故障ではありません。

**残高はどこで見る？** `tansr init` のサマリーカード、TUI のステータスバー（1 元を下回ると常時表示の警告に変わる）、コンソール。残高が尽きるとプラットフォームのモデル呼び出しは課金ゲートで拒否されますが、ローカル機能には影響しません。

**なぜ新しいセッションは 429 なのに古いセッションはまだ使える？** プランの同時実行数の上限到達（`plan_concurrency_exceeded`）は**新しい**セッションだけを拒否し、実行中のセッションは切断しません。30 秒後に再試行するか、プランをアップグレードしてください。詳細は[アカウントと請求](/ja/support/account/)。

**1 回の呼び出しでいくらかかった？** TUI の `/cost` はモデルごとに行を分けて集計します。`/usage` で token の明細、`/context` でコンテキストのどの部分にお金がかかったかを見られます。

## セッションとデータ

**セッションはどこに保存される？アップロードされる？** CLI のセッションはこのマシンの `~/.tansr` に保存されます（ログイン後はアカウントごとに分離）。プラットフォームは端末のセッション内容を保存せず、計量だけを行います。詳細は[セキュリティとプライバシー](/ja/security/)。

**前回のセッションをどう再開する？** TUI では `tansr --resume` でセレクターを開くか、`/resume`。スクリプトでは `--resume <id>` / `--continue`。

**セッションディレクトリが大きくなり続ける。どう掃除する？** `tansr sessions prune`（デフォルトは一覧を表示するだけ。`--apply` で初めて削除。当日のセッションと使用中のセッションは決して削除しない）。

**コンテキストが満杯になるとどうなる？** ターン間で水位に応じて自動的に圧縮されます。`/compact` でも可能です。圧縮サマリーの末尾には圧縮前の完全なトランスクリプトのパスが付き、詳細を後から確認できます。

**会話を 1 回分エクスポートしたい。** `tansr sessions export <id> [--format md|json] [--out パス]`。キーは自動でマスキングされます。

## エラーとトラブルシューティング

**最初に何をする？** `tansr doctor`。ネットワークを使わずに、設定、モデル解決、認証情報の保存先、プラットフォームモードの帰属、プラン、メディアツールの出所を出力します。終了コード 1 だけがブロッキングです。読み方は[トラブルシューティングガイド](/ja/support/troubleshooting/)。

**エラーコードはどこで調べる？** [エラーコード表](/errors/codes)にすべての機械可読コード、HTTP ステータス、再試行可否が載っています。

**「モデル provider が未設定」と言われるが、ログインは済んでいる。** `tansr doctor` の `localProviders` セクションを見てください。プラットフォームモードではローカルの providers はデフォルトで枝刈りされるので、これは想定どおりです。あるいはエスケープハッチにいる可能性があります。

**モデルが画像 / 音声ツールがないと言う。** `tansr doctor` のメディアツールの行を見てください。`none` は通常、管理者がまだアカウントに対応するメディアプールを開いていないか、このマシンがまだ新しい設定を取得していない（セッションを一度再起動する）ことを意味します。

**権限が常に拒否される。** ヘッドレス / サービス形態には確認のチャネルがなく、「確認」は一律で拒否にフォールバックします。`--allowedTools` や `--permission-mode` で権限を開き、環境の分離を組み合わせてください。SDK 側では `permission.askUser` を接続する必要があります。

## 開発者向けの接続

**SDK の 3 つのモデル取得元のどれを選ぶ？** 端末への配布はトークン方式 `{ token, baseUrl }`、自分のサーバースクリプトはマネージド方式 `model: 'エイリアス'`、テストは注入方式。3 方式は互いに排他です。

**セッションサービスに store を接続しないとどうなる？** プロセスが再起動した瞬間にすべてのアクティブセッションのコンテキストが失われ、`resume` は常に `409 resume_unavailable` になります。本番では必ず接続してください。

**モバイルでネットワークが切れたらセッションは失われる？** 失われません。SDK は `Last-Event-ID` で再接続し、gap があれば `/history` から再構築し、サーバー再起動後は store から resume します。3 段階の復旧チェーンはすべて自動です。

**プッシュ起動には何を接続する？** セッションサービスは webhook のフックだけを残し、プッシュチャネル（FCM / APNs / 各メーカー）はあなたが接続します。[v2 プロトコルと webhook](/ja/serve/v2-and-webhooks/)を参照。

**appkey が漏洩したら？** すぐにコンソールでローテーションし、サーバー側の環境変数を更新して再起動します。古い appkey は即時無効になります。

## まだ解決しない？

`tansr doctor` の出力（キーの値は含まれません）と、遭遇したエラーコードを添えて、[サポートに連絡](/ja/support/contact/)してください。
