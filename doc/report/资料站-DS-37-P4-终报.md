### 1.1 ① 剥 adminKey —— 实现要点

- 触发条件与实因:源契约 `contract/openapi.json` 两条 `/v1` op 的 `security` 含 `{ adminKey: [] }` 替代项(`POST /v1/adjudicators/{id}/evaluation-report` = `[{bearerAuth}, {adminKey}]`;`GET /v1/adjudicator-pool/artifact` = `[{}, {bearerAuth}, {adminKey}]`),既有生成器按「被引用才保留」把 `components.securitySchemes.adminKey`(头 `x-tansr-admin-key`)一并带进公开副本 → REST 参考页 Security 段向开发者展示拿不到的管理密钥方案。源契约无顶层 `security`;不含 adminKey 的 op 227 条无 `security` 声明(保持原样)。
- 修法(`filterPublic` 纯函数内、既有前缀 / tag / OPTIONS 过滤之后):`stripBlockedSecurity(security) → { kept, stripped }` 剔除含黑名单键的替代项(匿名 `{}` 与其余替代项原样、序不变;非数组视为无声明);每个公开 op:`stripped > 0 && kept.length === 0` → 整条不出并入 `dropped.security`;`stripped > 0` → 入 `strippedAdminKey` 并 `op.security = kept`;只剩被剔 op 的路径整条不出(沿「只剩预检的路径整条不出」同一 `opsOf(out).length === 0` 判)。顶层 `security` 同法:输出为剔后数组(可为空);顶层剔空时未自带 `security` 的 op 继承的即纯管理鉴权 → 同样不出并计 `droppedBySecurity`。引用集 `usedSecurity` 改为**剔除之后**收集(含剔后的顶层),`securitySchemes` 沿既有逻辑自然落掉 adminKey,无需另写删除。`stripOpExtensions` 返回浅拷贝,改 `security` 不触源对象(卷多次 `filterPublic(source)` 互不污染)。
